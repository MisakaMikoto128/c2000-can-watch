# docs/移植指南.md（Watch 仓库）

## 1. 换芯片 / 换板卡

| 改动点 | 文件 |
|---|---|
| Flash 扇段表与 RAM 布局 | `watch_demo/linker/28002x_flash_standalone_lnk.cmd` |
| 位域头文件 | `F28002x/`（TI 官方对应型号分发） |
| CAN 引脚、DCAN 实例、位时序 | `HDL/HDL_CAN.c` |
| CRC 校验窗口 | `can_dbg_crc.h` 的 `CAN_DBG_CRC_MAX_WORDS`（独立运行覆盖整片 Flash；与 Bootloader 共存时按实际 App 区收紧，上位机 `watch.py` 的 `APP_BASE_WORD/APP_WINDOW_WORDS` 同步改） |

## 2. 接入自己的应用

1. 把 `can_app.c/h`、`can_dbg*` 五对文件、`can_dev.h`、`app_config.h` 拷进工程。
2. 主循环保留 `can_app_poll()` 调用（收发与事务推进都在里面）。
3. 想观察哪个全局变量，直接在 WATCH 页加名字即可，固件侧无需登记。
4. 不想要调试口：`app_config.h` 里 `CAN_DBG_ENABLE` 置 0，全部接口内联为空实现，零占用。

## 3. 上位机配套

- 符号解析依赖 ELF/DWARF（CCS EABI 输出直接支持）；COFF 产物需 TI 的 ofd2000.exe（与 hex2000 同目录，或用环境变量 `HEX2000` 指路）。
- 0x35 校验窗口两端必须一致：固件 `CAN_DBG_CRC_MAX_WORDS` 与上位机 `watch.py` 的 `APP_BASE_WORD`/`APP_WINDOW_WORDS`。

## 4. 验证清单

1. 烧录后上电，上位机广播 0x20 → 应答版本 1.0.0、B6 bit0=1。
2. 观察页选 `watch_demo.out` → 0x35 校验显示“校验一致”。
3. 添加 `g_demo_counter` 开始观察，数值持续递增；帧统计“残帧 0 · 超时 0”。
4. 写 `g_demo_setpoint`，`g_demo_wave` 幅值随改随变。
5. 尝试写 Flash 地址 → 0x34 状态码 1（拒绝）。
